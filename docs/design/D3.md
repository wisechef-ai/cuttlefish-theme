# D3: working-state CPU (budget: ≤ +6.0 pp at ≥ 4 field updates/s)

Measured on the real Desktop v0.22.7 under a GPU-less private Xvfb, with the evidence harness's own scenario (8 sessions, the working session focused, the plugin toggled through Capabilities, 20 s settle, 62 s windows, renderer + GPU pids). Perf-only copy of the harness: `tools/design/capture_perf.ts`; variants built by `tools/design/d3_variants.sh`, run by `tools/design/d3_run.sh`. Each variant = two (plugin off, plugin on) window pairs; pp = on − off of the same pair.

| variant | change | updates/s | pair 1 | pair 2 | mean |
|---|---|---|---|---|---|
| v0 | HEAD (b7442b2 + design commits, product code untouched) | 5 | +8.0 | +7.2 | **+7.6 pp** |
| v3 | 4 updates/s only (frame gap 240 ms, clouds fps 4) | 4 | +8.6 | +6.1 | **+7.4 pp** |
| v1 | v3 + drop circles with alpha < 0.08 from the serialised field | 4 | +6.3 | +5.6 | **+5.9 pp** |
| v2 | v3 + drop circles with alpha < 0.20 | 4 | +5.1 | +5.0 | **+5.0 pp** |

(The brief quotes +10.8 pp for HEAD; this run measured +7.6 pp at 5 updates/s. Noise between pairs is ~1–2 pp, so differences under ~1 pp are not real.)

## Contract check of the techniques considered

| technique | verdict |
|---|---|
| compositor-only motion (`transform`, `opacity`, `will-change`) of a pre-rendered layer | **outside the contract**: oA_part5 allows only `--*` and `background*` on `[data-chat-surface]`, `--*` on `:root`/`html[data-cf-…]`; `::before/::after` are forbidden (R-S1: they paint over text); the plugin has no slot behind the transcript; the rim must stay static (P3.2b) |
| constant data-URI layers moved with `background-position` | legal by the allowlist but **fails locked P3.4**, which needs the field's SVG layer text to differ between frames; and any `background*` change repaints the whole surface anyway |
| cycling K distinct pre-rendered layers | legal, already what the memo does; it saves the SVG build, not the style/paint/raster |
| 4 updates/s (the contract floor, O4.1) | legal; v3 shows it alone is not enough |
| culling near-invisible circles from the **serialised** field (domain `renderField` untouched, so the classifier is unaffected) | legal if ≥ 40 circles stay in the layer (P3.1/P3.4) |

## Verdict

**in_contract: the 4 updates/s + cull technique is legal only if the cull keeps ≥ 40 circles; as measured it is not.** v1 (+5.9 pp mean, one pair at +6.3) is within noise of the budget and its cull leaves as few as 32 circles in the layer at some cloud phases (counts per phase over one cycle: 105, 96, 76, 32, 56, 95), which would fail P3.4's "≥ 40-organ scatter while it moves"; v2 (+5.0 pp) leaves 14–55 circles and fails it more often. A legal variant (keep the 40–48 highest-alpha circles) was **not measured**; expect it between v1 and v2 (~5.5 pp), but that is an estimate, not a measurement. No compositor-only technique is inside the locked contract. The budget was not bent: nothing above is claimed as met.

Next step for the coder (measure before claiming): implement "4 updates/s + keep the 48 highest-alpha circles" in `adapters/painter.ts` (after `renderField`, before `toSvg`), rerun `tools/design/d3_variants.sh` / `d3_run.sh` with that variant, and report the pairs.

A headless-Chromium proxy (`tools/design/d3_proxy.mjs`) was tried first and discarded: its page is tiny and cost ~0.1 pp/update, an order of magnitude below the Desktop, so it cannot rank techniques.
